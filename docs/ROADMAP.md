## Games Archive States

- Owner clarification: Session Logs holds games the owner is playing or may return to; Past Logs holds completed finite games or games deliberately retired. Online/live-service games remain in Session Logs while temporarily inactive. They move to Past Logs only by the owner's choice, for example after quitting permanently. Do not infer placement from single-player/multiplayer labels, achievement percentage, elapsed time or Steam activity.
- Separate manual placement (`Session Logs` / `Past Logs`) from current activity. Proposed Session states: `Active` / `Inactive`; `Ongoing` is not agreed wording. Keep one existing record and all its notes when moving either direction. Monster Hunter and similar hybrid games can return from Past to Session for DLC, then go back when the owner is done. A completed game stays completed unless the owner deliberately updates its authored state; a new note or Steam sync must not move it automatically.
- Implemented locally in `v1.43.0`: `gamePlacement` is an explicit Session/Past choice independent of authored Status; optional `gameActivity` is Active/Inactive, with a fallback to the existing Status. React, static and Studio use matching placement/display rules. Session cards display activity while entry headers retain Status and show explicit Activity separately; recommendation/completion values are untouched. Moving to Past clears the dashboard pin but does not mark a game completed. Legacy files retain their original status-based grouping and freeze placement on the next save; older drafts and older save clients preserve existing explicit values. Save/export tests cover DLC returns, retirement, activity reset, enum validation, notes/progress preservation and static output, using temporary records/repositories only. Browser testing used a disposable, storage-free Inspector fixture, then removed it. No owner records were migrated, and Steam automation is not enabled by this change.
- Consider a small optional `Subscription` descriptor alongside Active/Inactive for games such as FFXIV or WoW, not a separate archive lane or a third activity state. Agree on the label/placement first. Do not track billing, payment details, renewal dates or infer the owner's subscription status from Steam; this is a public archive, not account management.
- DLC/new-note visibility: reuse the existing note/activity freshness signal where practical rather than duplicating the record or adding a separate timer system. The current 48-hour New window is a candidate, not a newly agreed duration. Decide where a temporary highlight belongs and its duration before implementing it.
