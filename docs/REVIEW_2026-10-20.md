# Reliability And Security Review

Review date: 20 October 2026. Working version: `v1.36.25`. This batch continues the Notes Page work and the issues recorded in [the checkpoint](PROJECT_CHECKPOINT.md). It is not a deployment or a claim that all possible vulnerabilities have been eliminated.

## Fixed

- Static publish cache tokens now replace the complete query value, including dotted versions. The shared helper in `scripts/static-cache.mjs` preserves unrelated query parameters and fragments, and leaves image URLs alone. The static-shell validator checks dotted/numeric/missing tokens, single quotes, extra parameters, unchanged media URLs, and repeated application. No publish was run to test this.
- Top-level Notes Page rows now carry `note-entry--indexed`. Their CSS targets the row's direct summary/body, so nested legacy accordions keep their own header layout. Real date elements now receive the date styling class in both React and static renderers.
- Studio uploads now check a supported file signature against the supplied MIME type and assign the stored extension from that verified type. A file named as HTML cannot retain an HTML extension through the image upload path. Original media already in the archive was not rewritten.
- Publishing checks all root `.env`/`.env.*` filenames rather than only a few named variants; `.env.example` remains permitted and subject to the text scan.
- The private-path scan now detects generic Windows/macOS/Linux user-directory paths, instead of embedding the owner's local account name in its rule.

## Security Evidence

- `corepack pnpm audit --json`: zero reported advisories, across 66 dependencies in the returned audit metadata. Dependency versions and the lockfile were not changed.
- Tracked text scans found no matching private user-directory paths or recognizable credential patterns after replacing the account-specific scanner rule. Git tracked no `.env*` files, local shortcut, or mockup.
- Source review checked the local Studio request guards, media storage paths, scoped publisher, and text/media rendering. Public Pages has no writable Studio endpoints; local handlers remain development-only and require loopback request metadata.
- Live tests sent a foreign Origin to the entry, media, changes, and publish routes. Each returned `404` before performing the requested action. A local request containing HTML labelled as PNG returned `400` before writing a file. These tests did not save records or execute publishing.
- Pure helper checks accepted headers for PNG, JPEG, WebP, GIF, MP4, and WebM; empty payloads, HTML payloads, and an unsupported MIME type were rejected. Signature checks identify a format boundary; they are not full decoders or malware scans.
- A Pillow metadata inspection found no GPS/artist/copyright/owner/serial tags in 37 JPEG files under `public`. Other metadata formats and the visual contents of every screenshot were not comprehensively reviewed.
- Personal journal writing is intentionally public content. Credential/path scans do not decide which stories should be shared; retain the owner's editorial review and do not automatically redact or delete entries.

## Notes Layout Evidence

The local React archive was checked through the connected Chromium browser:

- A long Persona 5 Royal note retained an inset body with 24px padding, a 16px bottom margin, and the record scroll area's 32px bottom padding at the initial 1280x720 viewport.
- Focusing the final row and reaching the end of that scroll area showed approximately 51px between the final row's bottom and the scroll viewport's bottom.
- At 390x844, the row used the mobile date/title columns and 14px body padding; there was no document horizontal overflow.
- At 1920x1080, seven indexed rows and seven styled dates were present, with no document horizontal overflow.
- React and static markup use the same indexed-row/date classes. The static shell passed source/data validation; it did not receive a separate live visual check in this batch.

The temporary browser tab was closed, its viewport override was reset, and the temporary loopback server on port 3011 was stopped. No listener remained on that port when checked.

## Performance Still To Investigate

Firefox smoothness remains open. The available browser connection exposed Chromium, not Firefox, so this batch did not produce a Firefox trace or a measured cross-browser comparison. An installed Firefox executable alone is not evidence that it has been profiled.

The browser check confirmed that Memory State child animations have `animation-play-state: paused` while an entry has focus. The review did not remove effects or change the archive-access timing.

Useful next profiling targets:

1. Boot and first record access, compared with subsequent opens, using the same viewport, content, and cache state.
2. Static `render()` replacing `root.innerHTML` during navigation and record opening/closing.
3. Large translucent surfaces, filters, blend modes, and animated gradients; establish paint/compositing cost before simplifying their appearance.
4. Long note DOM after opening and collapsing several notes; bodies remain mounted after their first expansion.
5. Local Studio's synchronous publish/Git subprocesses. These can stall the local server and must be distinguished from public Pages rendering costs.

Other unfinished reliability work includes invalidating same-path media in the cache-first service worker, save/export failure recovery, and avoiding divergence between React, static rendering, and Studio. The owner's new visual observations should be added as a separate, concrete issue list when supplied.

## Verification

TypeScript checking, validation of all 46 content records, static-shell validation (including service-worker syntax and cache-token cases), static runtime/publisher syntax checks, `git diff --check`, and the Next production build passed. Media helper and live request-boundary checks passed as described above. The installed TypeScript and Next executables were invoked directly for the final checks/build, avoiding another Corepack network lookup.

No dependency install, application publish, record edit, commit, or push was performed as part of this review. Corepack obtained/used the pinned package manager to run the temporary dev server; that is separate from installing project dependencies.
